## Notes

**Rows 4 and 6 are `(story-originated)`** — both come from retro 21 rather than from spec 44. Row 4 is *only `ralph`'s prompt template is operative*: a change landing solely in the override table documents a behaviour the loop does not have. Row 6 is *state a number, then assert it against what it measures*, applied to the `**Length: N characters**` block epic 43-02 installed.

**Row 3 repeats row 2's criterion** under AD4 rather than inventing a second one. FR8 requires the evidence-bearing tag; AD4 says what the evidence is (the untraced count and requirement total). One criterion satisfies both.

**Row 3 was satisfied with the evidence *beside* the tag, not inside it — and that is forced, not a preference.** The ralph-wiggum stop hook compares the `<promise>` tag's contents to the `completion_promise` frontmatter with literal string equality after whitespace normalisation (`[[ "$PROMISE_TEXT" = "$COMPLETION_PROMISE" ]]` in `stop-hook.sh`). Anything appended inside the tag never matches, so a tag carrying counts would run the loop to its iteration cap on a finished epic — the promise would be unfalsifiable *and* non-functional. The template therefore prints the counts on their own line next to the bare promise token, which satisfies what FR8 asks the evidence for: a fabricated promise and an earned one are distinguishable in the log. AD4's wording assumed the tag could carry payload; it cannot.

**What verified rows 1–6.** Row 1 has a real oracle: one predicate over one file, with mutated copies removing each side in turn, both of which the predicate must reject. Rows 3 and 4 are checked the same way, row 4's control being a copy carrying the table row with the template clause stripped — the exact shape of a table-only change. Row 6's figure is extracted and compared, never pinned, and it *fired*: adding the completion clause took the template from 1,875 to 2,635 characters and the suite failed until the figure was corrected, which is what stating a number is for. Rows 2 and 5 are regression nets over prose plus the negative structural checks — `ralph` globs no matrices and reads no Verified column — and were verified by reading the finished sites.

**The strongest assertion in the suite is the correspondence one.** The command the template names is extracted from the template, run against fixtures built to be delivered and outstanding, and the codes it returns are compared to the codes the template's own branches name. Asserting the script's exit codes and the template's prose separately does not assert that they refer to the same thing: changing the template's `on 3` to `on 4` left every other assertion passing, and the branch could never have fired.

**What verified rows 7–8.** Row 7 is a regression net over the documented procedure — the Input section's empty-arguments fallback and the four steps of 1a (the glob, the Complete/retired filter, the stop message, the confirmation gate) — each with a mutation control: removing the fallback line fails one assertion, narrowing the glob fails another. It is a net rather than an oracle, and deliberately so: `cpm:ralph` is prose, the discovery procedure is executed by a model, and nothing in the suite launches a loop. What is checkable is that the procedure still says what it said.

Row 8 has one real oracle among its checks. The `must NOT` is about *behaviour*, and the only behaviour Story 1 could have changed for an existing invocation is the completion command, which takes `{epic_glob}` — a path list every input shape produces. The suite extracts that command from the template and runs it against a **two-epic** list, once mixed (exit 3) and once all-delivered (exit 0). Mutating `coverage-rollup.sh`'s epic loop to process only the first path fails that assertion and **only** that one: every single-epic assertion in the suite still passes. The rest of row 8's evidence is structural — the four documented argument forms are still present; step 1f warns and offers "Continue anyway" rather than aborting, so a missing script cannot turn a working invocation into a failing one; and 1f sits between 1a and Step 2, so it is in the sequence every shape runs rather than conditional on one. Corroborated by the diff: `git diff cpm/skills/ralph/SKILL.md` removes exactly three lines, each replaced in place — the variable list (expanded), the `**Length:**` figure (corrected), and the template line (extended). Nothing governing an existing input shape was deleted.

**FR7 (row 9) also has rows in epic 44-02's matrix**, on the `cpm:status` phase and the stakeholder artifact. The criterion text is identical in both, so whichever epic's gate runs second re-reads the full set of sites rather than trusting the first.

**What verified rows 9–10, and what the second FR7 gate actually did.** This gate ran second, so "every site" was re-derived rather than inherited. Two passes: a sweep of `cpm/skills/*/SKILL.md` for anything presenting a total (`N of M`, `rows marked`, `verified rows`, `aggregat`, `delivered`, `untraced`) outside the three known skills, which surfaced only non-subjects — `cpm:audit`'s effort aggregate counts estimates, not marks, and `cpm:inspect`'s line reports coverage rows *sceptically* ("rows marked verified with no test naming them") rather than totalling them; then a read of all four sites in full. `cpm:status` Phase 3b, the stakeholder page, `cpm:do`'s batch summary and `cpm:ralph`'s completion line each carry the statement in their own words, and `status`'s "the untraced count is the part of this section that discriminates" and `ralph`'s "it counts rows in these epics, not requirements in a spec" agree rather than contradict.

Row 10's oracle is the mutation set. Removing the what-it-counts clause from the printed line fails one assertion and only that one; removing the named untraced measurement, or the sentence deferring spec scope, each fails exactly one more. The statement is asserted on the **template line**, not the prose around it — moving it into the prose alone leaves the suite green, which is correct and deliberate: the stop hook feeds the template back verbatim and the loop reads nothing else, so a label living only in the surrounding prose would be a label on something the operator never sees.

**The `✓`-count inventory under-reports `ralph` by design.** `test-aggregation-labelling.sh` tripwires on `✓` characters per skill, but `ralph`'s aggregation site — the template's completion line — prints its total in words and contains no `✓`; the one `✓` in `ralph/SKILL.md` is the paragraph documenting it. The count is a tripwire for *new* sites, not the site list; the four rostered sites are asserted individually. The inventory's previous assertion, "cpm:ralph presents no aggregated ✓ yet — 44-03 adds both the site and the label", was written by 44-02 to fail the day this story landed, and it did.

**Rows 3–6 show `—` for Spec Test Approach** because AD4, NFR5 and the two story-originated criteria are not in spec 44's Acceptance Criteria Coverage table, which tags the must-haves plus NFR1 and the two Invariants.
