# The row-narration rule gets its checks, and a defaulted column goes unsaid

**Number**: 10  
**Status**: complete — Shipped in 0.7.3 as commit 79f49f5. An increment on quick 09 / 0.7.2, which fixed the narration but shipped `Saying what a row holds` with nothing asserting it and no rule about a column sitting at its default. Written after the fact: the MCP server held a stale handle on the database `dpm-import.js` had replaced, so every write was refused until the plugin was reloaded.  

**Closed**: 2026-09-02T10:30:00.000Z  

## What changed, and how it was verified

Two files. `dpm/tests/corpus.test.js` gained four tests and two reading functions; `dpm/shared/skill-conventions.md` gained one paragraph.

**0.7.2 fixed the narration and shipped no check over it.** Quick 09 wrote `### Saying what a row holds` into `Conversational Output` — narration names what a column means, never the value it holds — and every claim it makes is prose in a file two suites already read as text. The checks were available and simply absent, which is the state a later edit softens a rule from without anything going red.

The four tests are separate tests with separate readings, and that is the design rather than an accident of writing them one at a time. `forbidsTheStoredValue` and `requiresSilenceAtTheDefault` return complaints instead of asserting, so each control can drive the reading on a rule mutated on purpose and read what comes back — the shape `admitsRunSideReason` uses one subsection down. Retro 08's finding is why: a check sharing a test with the positive it complements is only verified when the mutation happens to fail that positive first, so a rejection gets its own test with its own control or it gets no evidence at all.

**The principle is asserted in three parts because one is not enough.** The bare statement is the sentence every run already believes it is following; the worked example — `not "Story 1 has plan: 1, so I'll explore"` — is the narration actually caught in the wild; and the breadth clause is what stops it reading as a rule about one column, which is how the next column repeats the incident. Each has its own control.

**The argument exemption earns a test of its own.** Without it the section contradicts two green suites that pin the argument sites: `epics` Step 3 must carry the literal `plan: 1` and `do`'s planning step must name a backticked `plan`. A rule forbidding the value everywhere would put both in violation of the conventions, so the test asserts the exemption, asserts the test that decides which side a sentence falls on, and then checks both sites still carry the value — making the exemption load-bearing rather than decorative.

**The default clause is the half 0.7.2 was missing.** It gave the mark words for both states and never said to omit the unset one, which licenses a line against every row. `plan` is unset on eight stories of nine, so *planning this one inline* against each is a line the reader pays for in order to learn nothing — and the one story that does need designing in full stops standing out, which is the whole reason the mark is there. Bounded to where the value is news or where the distinction is the step's own subject, so a step that routes on it and a report of what a run cleared both still say it. Same argument the Disposition rule already makes for a heading over an empty block.

**Verified by planting defects, not by reading the assertions.** Renaming the section heading turned all four red, the first reporting `there is no row-narration subsection to read`. Mutating the default clause alone turned exactly one red and left the other three green. `npm test` is 968 of 968 and the guard reports 56 projected files matching the database.

## Two things this run found in the ground around it

**This work was done twice, and the first time was against a stale checkout.** The run reached a complete fix — its own convention subsection, a local edit to `ralph`, four tests, a version bump to 0.7.2, a quick record and a commit — before `git push` was rejected. `origin/main` was two commits ahead and the fix had already shipped as 0.7.2 on 30 August, three days earlier. Nothing was lost, because the commit was local and unpushed, and the recovery was to drop it, fast-forward, and re-apply only the increment that survived comparison: the tests, and the default clause. The general shape is that a `git fetch` costs nothing and a full quick-path run does not, so on a repository with another session pushing to it the fetch belongs before Step 1a rather than after Step 4.

**`dpm-import.js` replaces the database file, and a running MCP server does not notice.** The guard named the remedy correctly — `.dpm/dpm.sql` had changed and the database had not, which is what a pull leaves behind — and the import rebuilt the file. Every read after that was served from the replaced-but-still-mapped file: `list_quick` returned this run's own discarded quick 09 rather than the one the pull brought, which is how the stale handle was identified. Writes failed as `Internal error`. It is not the NFR7 lockout, which reports a version skew and applies when the schema is ahead; both sides were at schema 27. Reloading the plugin fixed it, and this record was written afterwards.

That second one is worth stating as a rule rather than an anecdote: **after an import, the server is serving the old file until it restarts, and its reads are as wrong as its writes.** The reads are the dangerous half, because they succeed.
