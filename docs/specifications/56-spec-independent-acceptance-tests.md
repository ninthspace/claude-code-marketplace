# Spec: Independent acceptance tests and real source samples

**Date**: 2026-11-11  
**Amended**: review 13 (docs/reviews/13-review-independent-tests.md) and the user's decision — a pre-build red is held in the run directory until step 3 writes its `Evidence` line, since any `Evidence` line reads as proof (FR8); the `sample due` check split into the user's story and a marked story blocked by it (FR2) (2026-11-11)  
**Source**: the user's request (2026-11-11), "Separate who defines 'correct' from who builds"; the user's decisions (2026-11-11): the independent agent tests at the system's boundary only; `plan` marks the stories that get one; an independent test's failure before the build is its red; with no real sample, `plan` asks once and the work goes on, flagged, with a sample criterion waiting on the user

## Problem Summary

`do` builds a story and writes the tests that prove it, so the code and its tests come from one set of assumptions; a wrong assumption passes both. The red pass (`cpm-next/skills/do/SKILL.md` step 4) proves a test *can* fail, not that it tests the right thing, and the `auditor` (`cpm-next/agents/auditor.md` checks 1 and 5) judges the builder's tests rather than writing its own. The case that prompted this: an API ingest whose model treated the wrong attribute as its key dropped records that shared it. The API returned every record; no stage caught the loss, because every invented fixture made every field unique, so the wrong key never collided. Earlier classes of the same family (`check-cannot-fail`, `instance-not-rule`) were answered with rules added to `plan`, `do` and the auditor, all still applied by the builder to its own tests.

This spec makes a real sample of each data source, and the source's documented identity, part of the spec; adds the identity and conservation criteria any stored records must meet; and gives a story `plan` marks a second author: a `test-writer` agent that writes the story's acceptance tests at the boundary the spec names, from the spec, the story and the samples, before any of the story's code exists, and which the builder may not change.

## Functional Requirements

### Must Have

- **FR1 — Data sources in the spec.** The contract's Spec template (`cpm-next/shared/artifacts.md`) gains a `## Data Sources` section, after `## Testing Strategy`, present only when the spec reads records from outside the codebase (an external API, a file feed, an import, a webhook). One bullet per source: `- {source}: identity {field(s)} ({where the source defines it}) — sample: {repository path} ({YYYY-MM-DD}{, version}) | sample due: {documentation path or URL}`. The identity is the source's own unique key for a record, taken from its documentation or contract, never inferred from field names. A sample is the smallest real extract from the source that holds every record shape the spec uses, two consecutive pages where the source pages its results, and records that share non-identity values where the source has them, under 100 KB, committed under the project's test fixtures. Redaction replaces every personal value and secret consistently (one stand-in per distinct value across the whole sample, so records that shared a value still share it and references between records still resolve), an identity that is personal data included; it removes no record and no field a criterion names. — AC: the contract holds the section, the bullet form, the sample's limits and the redaction rule, and states when the section is present `[manual]`
- **FR2 — Plan asks for samples.** When a spec has a data source, `plan`'s question round (step 2) holds one question, for every source together, asking for a real sample (a path, or leave to fetch one through access the session already has) and the source's documentation; it never asks for credentials. `plan` redacts a supplied sample as the contract says and writes it at the path the bullet names, leaving the commit to the user. With no sample, the bullet reads `sample due`, the spec's Assumptions say the tests are built from the documentation's examples, and the spec's user-checks epic holds two stories: one whose only criterion is the `[user]` step of placing a redacted sample at the named path, and one blocked by it, marked (FR4), whose test-proven criteria are FR3's over that sample, written by its own test-writer in new files, so no writer starts before the sample exists. — AC: `plan/SKILL.md` states the question, the redaction, the `sample due` path and the user-checks story `[manual]`
- **FR3 — Identity and conservation criteria.** `plan`'s Epics rule adds: a story that stores, upserts or merges records has, for each record type, criteria that (a) records distinct by their identity that share every other attribute the code could mistake for a key (name, title, date, parent, position) are all kept, with its control (a store keyed on any non-identity attribute fails it), in a fixture taken from the sample with such records added where the sample has none; (b) every record received is accounted for: created, updated, unchanged or skipped, their counts summing to the records received, each skip with its reason recorded where the spec says; (c) the same records delivered again, or the same identity twice in one delivery, change nothing beyond the first, with its control (a store that inserts on repeat fails it). The identity is the **Data Sources** bullet's or, for records the codebase defines, the spec requirement's. — AC: `plan/SKILL.md` states the three criteria with their controls and where the identity comes from `[manual]`
- **FR4 — Plan marks the stories and names their boundary.** `plan` gives a story `**Independent tests**: due` when it has a criterion a test proves and it reads a **Data Sources** source, upserts or merges records by an identity, imports or exports records, or serves an API other systems call, or carries `**Effort**: high`; a form that saves what its user typed is not marked for that alone. A marked story's criteria name its boundary: the entry point (route and method, command signature, job or listener with its input, or the component class a test mounts); the outbound seam a test fakes (the HTTP client and how it is faked, a disk, a file path, a queue); and the stored state a test reads (the tables or models, their identity columns, and where skips are recorded). These are decisions about data and integration that the spec makes, not interfaces of the code inside. — AC: `plan/SKILL.md` states the marking rule and the three parts of the boundary; the contract defines the field `[manual]`
- **FR5 — The test-writer agent.** A new agent, `cpm-next/agents/test-writer.md`, on `opus`, writes a marked story's acceptance tests. Its prompt holds the story, the spec (with **Data Sources**), the sample paths, the contract's path, the project's test command and formatter, its own scratch directory, and any files a stopped writer left for the story; it has none of the conversation. It reads the existing code and tests for conventions and boundaries, and writes tests only through the boundary the story names, asserting only what the criteria, the spec and the samples state: every criterion a test proves gets at least one test, the identity values in each sample are checked unique, and FR3's criteria are built from the sample. It writes only new files (tests and fixtures, in a directory the project's full run covers), may replace or delete a stopped writer's files it was given, edits no other file, runs the project's formatter on its files, and reports each file and, for each test, the criterion it proves. — AC: the agent file states its inputs, its limits and its report form `[manual]`
- **FR6 — Do runs it before the build.** For a marked story, `do` starts the test-writer before any of the story's code is written (in a batch, one per marked story, in parallel, after any schema-first story the lead runs and before fan-out), checks its report against the files, and rewrites the field as `**Independent tests**: {path} {blob}, … ({YYYY-MM-DD})` over every file the writer wrote, `{blob}` the first 12 characters of `git hash-object`. The lead then runs each story's independent tests, one story at a time and never beside another test run. A test that errors for a cause other than the boundary not existing yet (a syntax error, a bootstrap failure, a missing fixture) goes back to the writer. A test that passes is kept when it is a must-not or never criterion's, or asserts behaviour the code already has; otherwise it goes back to the writer, once, and then raises its criterion through **When a criterion looks wrong**. — AC: `do/SKILL.md` states the order, the pre-build run, the error and passing-test rules and the field rewrite `[manual]`
- **FR7 — The builder may not change them.** The builder makes the independent tests pass without editing the files on the field; the simplifier and the project's formatters are not run over them. Each criterion an independent test proves cites it in its `Evidence` line, beside any test of the builder's. A builder that finds an independent test wrong cites what contradicts it: a requirement, another criterion, or a `file:line` the story did not write. The lead (never a parallel subagent) starts a fresh test-writer with the spec, the samples, the story, the test and the citation, and it keeps or revises the test; a revision rewrites the field's blob for that file and appends ` — revised {YYYY-MM-DD}: {path} ({citation})`, and the revised test takes its red in the red pass. Each test is disputed once; a test kept after its dispute leaves the story to build to it or be marked blocked, with a signal. — AC: `do/SKILL.md` states the rules, the citation limit, the route through the lead and the cap `[manual]`
- **FR8 — The red before the build.** An independent test's failure in the pre-build run is its red (`red: {message} — before the build`) when the story's boundary already answered before the build (the route, command or component existed) and the failing assertion is the one that proves its criterion, not an earlier status, existence or setup assertion. Every other independent test, and one whose pre-build red was not yet written into its `Evidence` line when a run stopped, takes its red in the story's red pass, as the builder's tests do. `do` holds each pre-build red in the run directory until step 3 writes the criterion's `Evidence` line with it, since an `Evidence` line is read as proof by the contract's Complete and waiting rules, `do`'s resume and the mods; a run that stops loses them, and those tests take the red pass. — AC: the contract holds the form; `do/SKILL.md` states when it applies and where it is held `[manual]`
- **FR9 — The auditor checks them.** The auditor may run `git hash-object`. Its check 5 adds, each a Critical: a file on the `**Independent tests**` line whose blob differs from the one recorded with no ` — revised` note for it; a marked story whose field still reads `due`; a criterion an independent test proves whose `Evidence` line does not cite it; and a change the story made to shared test setup, test-runner config, factories or environment, or code that branches on the test environment or names a sample's values, that changes what an independent test checks. A `before the build` red is accepted when the test's file still matches its blob, the boundary existed at the story's start (checked with `git show` against the story's first commit's parent or the diff), and the failure text is what the cited assertion prints. — AC: `auditor.md` states each, and the allowed git commands include `hash-object` `[manual]`
- **FR10 — The runs know whose tests these are.** `shared/test-runs.md` adds: the files on a story's `**Independent tests**` line are in its targeted set; a failing test in a file on the line of a story not yet Complete belongs to that story, so it is neither pre-existing at a baseline nor a regression another story's run must fix, and the story closes only when its own independent tests pass; a fixture or factory file a story added that only that story's tests read is not wide reach. — AC: `test-runs.md` states the three rules `[manual]`
- **FR11 — Collisions are an unexpected input.** `do` step 4's and the auditor's check 6's lists of unexpected inputs add records that collide on an attribute that is not their key, and the same identity twice in one delivery. — AC: both lists name them `[manual]`
- **FR12 — No test-writer.** When the agent is not available, `do` writes `**Independent tests**: skipped — test-writer unavailable`, builds the story as an unmarked one and says so under **Found**; the auditor does not report that form. — AC: `do/SKILL.md` and the contract state the form; `auditor.md` exempts it `[manual]`

### Won't Have (this iteration)

- Independent tests for a small change (`docs/quick/`).
- Unit tests by the test-writer, or names of classes inside the code fixed in advance for it.
- A hook that refuses edits to independent tests; the auditor's blob check enforces it.
- Fetching samples with credentials, or committing a sample not redacted.
- Back-filling **Data Sources** or the field into existing specs and epics.
- Held-back tests shown only at audit.

## Non-Functional Requirements

- **NFR2**: `claude plugin validate cpm-next` and `claude plugin validate .` pass, and `claude plugin test` passes for cpm-next, cpm-next-models, cpm-next-progress and whats-next.
- **NFR3**: Each new form (the **Data Sources** bullet, the sample's limits and redaction, the `**Independent tests**` field in its states with its position in the header block, the `before the build` red) is stated once, in the contract; `plan`, `do`, `test-runs.md`, the auditor and the test-writer refer to it.
- **NFR4**: The words added to `plan`, `do`, `test-runs.md` and the auditor are measured with `wc -w` against `0a4e609`, and the README's Size bullet gives the counts; the test-writer's rules live in its own file, which only a marked story loads.

## Architecture Decisions

### AD1: A second author, before the build, at the boundary
The test-writer works before the code exists, so it cannot share assumptions the builder forms while building, and it tests through the boundary the spec names (the user's decision, 2026-11-11). It runs on the same model and reads the same spec, so its independence is partial; what it adds is a different author for the assertions and the obligation to build them from the sample (AD3), which is the stronger oracle. The boundary (entry point, outbound seam, stored tables and identity columns) is a data and integration decision a spec makes anyway; classes inside the code stay the builder's. Rejected: tests written after the build by an agent blind to the code (it would have to find the boundary in the code, and see the design), boundary plus named units (plan would fix interfaces of the code inside), and test cases as data the builder codes up (the builder would write the assertions).

### AD2: Plan marks the stories
Marking by the data-boundary rule and `high` effort spends the extra Opus agent where a shared wrong assumption loses or corrupts data (the user's decision, 2026-11-11). Plain form saves are left out so the rule does not reach every CRUD story. Rejected: every test-proven story (a config change gains an agent) and `high` effort alone (the ingest that prompted this need not have been marked `high`).

### AD3: The real sample is the oracle
A fixture invented by the person who wrote the code models the source and agrees with that model; a sample asks the source (library: "Ask the runtime the question rather than modelling its answer"). The identity comes from the source's documentation, never from a field's name, and the test-writer checks the sample's identity values are unique, which catches a documented identity that is wrong. Redaction is consistent so that it keeps the collisions and references the tests need. With no sample, the work goes on from the documentation and a `[user]` criterion holds the gap open (the user's decision, 2026-11-11). Rejected: blocking until a sample exists (stalls work behind access) and treating documentation as enough (a source that differs from its docs goes unnoticed).

### AD4: Rules kept, and the one narrowed
The request asked whether this lets existing rules go. `plan`'s control and instance rules, the red pass and the auditor's checks stay: the test-writer applies the control and instance rules to its own tests, and the builder's tests still need the red pass. The red pass is skipped only for an independent test whose pre-build failure is its own criterion's assertion against a boundary that already answered, since that failure shows the test telling wrong code from right and was taken before the builder could shape it (the user's decision, 2026-11-11, narrowed by the challenge). A failure against a boundary that did not yet exist shows only absence from presence, and takes the red pass. Rejected: removing the red pass for every test (builder tests on unmarked stories would lose all red checking).

## Scope

### In Scope
`cpm-next/shared/artifacts.md` (Spec template's **Data Sources**, the sample's limits and redaction, the story field, the red form, seed slugs); `cpm-next/skills/plan/SKILL.md` (step 2's question, section 3's Spec, Epics and Story fields); `cpm-next/agents/test-writer.md` (new); `cpm-next/skills/do/SKILL.md` (the loop's steps 1 to 5, the parallel rules, **When a criterion looks wrong**, resuming); `cpm-next/shared/test-runs.md` (the targeted set, wide reach, failures that belong to an open story); `cpm-next/agents/auditor.md` (its allowed commands, checks 5 and 6); the docs, `fixed.md`, the maintenance record and versions in FR13.

### Out of Scope
`review` and `status` (they read the new section and field as any other text), `worktree.md` (the field names the files, so the merge commit need not hold them), the mods' code.

## Testing Strategy

Prose changes are checked by reading each changed passage against its requirement, with `grep` for the required strings and for every place that restates a form, each hit accounted for (`[manual]`); `claude plugin validate` and `claude plugin test` for NFR2; `wc -w` for NFR4. The mods' parsers drop unknown `**Field**:` lines in a story's header block (`docs/maintenance/README.md`, "Unknown fields in the mods"), and match `**Acceptance Criteria**:` exactly (`whats-next/hooks/plan.ts:114`), so `**Independent tests**` needs no mod change; NFR2's suites confirm it. This spec reads no data source, so it has no **Data Sources** section; the first real use is a later spec with one.

## Assumptions

- Most tests of a brand-new feature fail before the build against a boundary that does not exist yet, so they take their red in the red pass; the pre-build red saves work on stories that extend a boundary that already answers.
- In worktree mode the writer's files are written and committed in the lead's checkout before fan-out (`do/worktree.md`, "commit the run's own work before each fan-out"), so they are outside the story's merge commit; the field names them, and the targeted set and the auditor read them from it.
- A dispute reaches the lead from a parallel subagent through its report, as its other failures do.
- New seed slugs: `shared-assumption` (the code and its tests share a wrong assumption) and `identity-key` (a record's identity wrong or inferred).
- A test-writer stopped part-way leaves files the field does not name; on resume `do` gives the untracked files under the test directories, created since the story started, to the new writer.
- Tests over a sample freeze the clock at the sample's date where the sample holds dates.
