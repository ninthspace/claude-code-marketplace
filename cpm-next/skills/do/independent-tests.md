# Independent tests

Read this file when a story in scope has an `**Independent tests**` line other than `skipped`, and read it again whenever it is not in context. It is part of `do` (`SKILL.md`, beside this file); a step, section or list it names is `do`'s unless this file holds it (**A dispute**, **The prompt** and the other bold labels here are its own).

A story whose `**Independent tests**` line reads `due` (the field and its forms are in the contract) has its acceptance tests written by the `test-writer` agent (`subagent_type` `cpm-next:test-writer`) before any of its code is written, and is built to them.

- **Order.** In a single build the writer runs after step 1 and before step 2. In a batch the lead starts one writer per marked story, in parallel, after any schema-first story it runs and before fan-out; a schema-first story that is itself marked has its writer run before the lead builds it.
- **The prompt**, as `do`'s **Audit** lists the auditor's: the story and the epic doc's path; the spec; the paths of the samples its **Data Sources** section names; the absolute paths of the contract and of `skills/plan/SKILL.md` (beside this skill's directory); the test command and the project's formatter; a fresh writer directory (`do`'s **Scratch directories and isolation**); and, on a resumed story whose line still reads `due`, the files a stopped writer left, found by `{epic file stem}-{story}` in their paths. A test sent back to the writer adds its file, why it came back, the failure text, citation or audit finding, and the files the story's build has changed.
- **The pre-build run.** The lead checks the writer's report against the files, then runs each story's independent tests, one story at a time and never beside another test run. This run does not rewrite `**Test run**`. A test that errors for a cause other than the boundary not existing yet (a syntax error, a bootstrap failure, a missing fixture) goes back to the writer. A test that passes is kept when it proves a must-not or never criterion or asserts behaviour the code already has, and otherwise goes back to the writer. Each test goes back at most once for each cause; after that, an error marks the story blocked with a signal, and a pass raises its criterion through `do`'s **When a criterion looks wrong**.
- **The red before the build.** A failure in this run that meets the contract's conditions for the `before the build` red is that test's red. The lead holds its failure text in the run directory and writes no `Evidence` line before the build; step 3 writes it into the criterion's `Evidence` line in the contract's form. Every other independent test, one whose held red was lost when a run stopped, and every test in a file a revision changed (**A dispute**), whose held red is then dropped, takes its red in the red pass (step 4).
- **The field.** After the last return to the writer, and in worktree mode after the commit before fan-out (a commit hook can reformat a file), the lead rewrites the line in the contract's form over every file the writer wrote.
- **The builder's limits.** No file on the line is edited, and neither the simplifier (step 2) nor the project's formatters run over them. Each criterion an independent test proves cites that test in its `Evidence` line, beside any test of the builder's.
- **A dispute.** A builder that finds an independent test wrong cites what contradicts it: a requirement, another criterion, or a `file:line` the story did not write. The lead, never a parallel subagent (whose report carries the dispute to the lead), starts a fresh writer with the prompt above, the test and the citation. The writer keeps or revises the test; a revision rewrites that file's blob on the line, appends the contract's ` — revised` note, and every independent test in that file takes its red again in the red pass. An audit finding that an independent test is wrong or proves too little is a dispute too, the finding being its citation: no fix edits the test, and a test the writer keeps leaves the finding dismissed with the writer's reason, given to the next audit. Each test is disputed once: a test kept after its dispute leaves the story to build to it or be marked blocked, with a signal.
- **No writer.** When the `test-writer` agent is not available, the lead rewrites the line `skipped — test-writer unavailable`, builds the story as an unmarked one and says so under **Found**.
