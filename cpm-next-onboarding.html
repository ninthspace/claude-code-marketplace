cpm-next

A planning-and-building method for Claude Code. This deck takes you from installing it to running your first spec end to end, in one afternoon.

  • What it is, and the six skills
  • The artefacts it writes in docs/

  • A first walkthrough: plan, review, do one story, status
  • Unattended runs, story effort, the two agents, staying up to date

Use the arrow keys or space to move between slides. Press T to switch light and dark.

What it is

An idea becomes tested code through a short chain of documents

  • cpm-next keeps a chain of Markdown artefacts in your repository's docs/ folder: a discussion record, a product brief, a specification, and epics made of stories with acceptance criteria.
  • Six skills cover the whole path. Each skill states what "finished" means and when to stop.
  • The artefacts are the only state. There are no progress files to clean up. The epic doc is the task list: you read it to see where a run is, and the next session resumes from it.
  • Each skill declares its model and effort. Opus plans and reviews. Sonnet builds. An Opus auditor agent checks every story before it closes. A Haiku scout agent answers lookups. status runs on Haiku.
  • It works for greenfield and brownfield projects. In a brownfield project, plan grounds every requirement in the current code.
The six skills

Each skill has a finish line

SkillWhat it doesFinished when
/cpm-next:partyDiscussion with named specialist personas (PM, Architect, Developer, UX, QA and others)A discussion record is saved and the next step is named
/cpm-next:planWrites whatever is missing of brief, spec and epics, from whatever already existsThe artefacts down to the epics exist and trace upward
/cpm-next:reviewIndependent challenge of the epics before they are builtCritical and Warning findings are fixed or waiting on you
/cpm-next:doBuilds stories, verifies each acceptance criterion with evidence, and has each story auditedEvery story in scope is Complete and the tests pass
/cpm-next:libraryCurates reference documents in docs/library/ that planning and building readDocuments carry complete front-matter
/cpm-next:statusRead-only report of where things stand and the next command to runNothing is written

party and review are optional. The minimum path is plan then do.

The artefact chain

What lands in docs/

Discussiondocs/discussions/
{nn}-discussion-{slug}.mdparty
→
Briefdocs/briefs/
{nn}-brief-{slug}.mdplan
→
Specdocs/specifications/
{nn}-spec-{slug}.mdplan
→
Epicsdocs/epics/
{parent}-{seq}-epic-{slug}.mdplan writes, do updates

Alongside the chain

  • docs/architecture/ ADRs, only for decisions that outlive one spec
  • docs/reviews/ review records
  • docs/retros/ retros written by do
  • docs/quick/ records of small changes made without an epic
  • docs/library/ reference documents every skill reads

Numbering

  • {nn} is one more than the highest number already used, in the folder and its archive. Numbers are never reused.
  • An epic's {parent} is its spec's number, or 00 when there is no spec. So spec 01 has epics 01-01, 01-02 and so on.
  • A level that would only restate the one above is skipped. A small change can go from a description straight to a 00- epic.
The epic format

Stories, criteria and tasks, as plan writes them

Example epic from Starling Library, an imaginary lending-library app used for every example in this deck. The whats-next and cpm-next-progress mods parse these fields, so the format is fixed.

# Loans CSV Export

**Source spec**: docs/specifications/01-spec-loans-csv-export.md
**Date**: 2026-10-08
**Status**: Pending
**Blocked by**: —

## Export the filtered report as CSV
**Story**: 1
**Status**: Pending
**Blocked by**: —
**Satisfies**: FR1, FR2
**Effort**: high

**Acceptance Criteria**:
- The export contains exactly the rows the report's current filters show `[feature]`
- A user without the reports permission receives a 403 response `[feature]`

### Add the export route and controller
**Task**: 1.1
**Description**: Route behind the reports permission that returns the CSV
**Status**: Pending

---

## Add the export to the reports menu
**Story**: 2
**Status**: Pending
**Blocked by**: Story 1
**Satisfies**: FR3
**Effort**: low
**Model**: haiku

Status values: Pending, In Progress, Complete. Epics may also be Superseded or Withdrawn, which only you set. A story is unblocked when its **Blocked by** is — or everything it names is Complete. A dependency on another epic names it by filename prefix, for example Epic 28-01-epic-setup.

Evidence and Audit

What do adds when a story closes

## Export the filtered report as CSV
**Story**: 1
**Status**: Complete
**Blocked by**: —
**Satisfies**: FR1, FR2
**Effort**: high

**Acceptance Criteria**:
- The export contains exactly the rows the report's current filters show `[feature]`
  - Evidence: tests/Feature/LoansCsvExportTest.php "exports only filtered rows", php artisan test --filter=LoansCsvExportTest, 4 passed
- A user without the reports permission receives a 403 response `[feature]`
  - Evidence: tests/Feature/LoansCsvExportTest.php "forbids users without the reports permission", same run

**Audit**: pass (2026-10-08), 2 findings fixed
  • Each criterion gets its own indented Evidence line: a test name and command, a file:line, or the manual step taken and what was seen.
  • The criterion line itself is never edited.
  • A story is Complete only when every criterion has an Evidence line. A Not met line leaves it blocked.
  • **Audit** is written in the same edit that closes the story. If the auditor is unavailable it reads **Audit**: skipped — auditor unavailable.
Installation

Install the full set at user scope

Inside Claude Code, add the marketplace once:

/plugin marketplace add ninthspace/claude-code-marketplace

Then install the five plugins. User scope is the default, so one install serves every repository.

/plugin install cpm-next@ninthspace-marketplace
/plugin install cpm-next-models@ninthspace-marketplace
/plugin install cpm-next-progress@ninthspace-marketplace
/plugin install whats-next@ninthspace-marketplace
/plugin install plugin-sync@ninthspace-marketplace
/reload-plugins
The suffix is the marketplace's name, ninthspace-marketplace, not the repository's. cpm-next@claude-code-marketplace resolves to nothing.

/reload-plugins loads the new plugins into the session you are in. Any other session that was already open needs it too.

What a mod is. A plugin of function hooks that runs inside Claude Code. Mods load like any plugin, run no model calls of their own unless stated, and are switched off and on with the plugin.
Per-project setup

The progress tracker and the /next pane

/progress-tracker NN

Run it once the spec's epics exist in docs/epics/. NN is the spec's number.

/progress-tracker 01
  1. Writes docs/specifications/01-build-order.json from the spec's epics, if it does not exist yet.
  2. Writes the page to .claude/cpm-next-progress/ and adds that folder to .gitignore.
  3. You ask Claude to publish the page. It becomes a private claude.ai artifact.
  4. The mod saves the link in the build-order file and keeps the table in step with the epic docs from then on.

Edit the build-order file to reorder, regroup, split a story into tasks, or add waitingOn. /progress-tracker on its own checks every tracker and prints what differs.

/next

No setup. The mod reads docs/epics/ and docs/specifications/ directly, with no model calls.

  • The pane lists every story not yet Complete, in build order, and every spec with no epics yet.
  • It opens by itself in a repository with work left when the terminal is at least 144 columns wide. /next opens it at any width and prints the list into the conversation.
  • A band above the prompt shows the next story, its next task, and how many stories are left.
  • Ask Claude (hotkey a) asks Sonnet for a short note on what to do next.
First walkthrough · 1 of 4

Plan

/cpm-next:plan a CSV export for the loans report
  1. Takes stock. Reads docs/, README.md, CLAUDE.md and, in a brownfield project, the code and test setup. It says what exists, what is missing and what this run will produce, then carries on.
  2. Asks once. Questions only you can answer, which would change scope, cost or a hard-to-reverse choice, come in one batch of up to four, each with a recommended default. Everything else it decides and records under Assumptions.
  3. Writes what is missing. Brief if needed, then the spec (MoSCoW requirements with labels such as FR1, measurable NFRs, decisions, scope, testing strategy), then epics. A non-trivial spec goes through a challenge pass by two or three personas first.
  4. Finishes with three headings: Needs you, Written and Next.

To talk an idea through first, run /cpm-next:party {topic}, type wrap up when done, then /cpm-next:plan {record path}. Do not type "exit" or "quit": those close Claude Code itself.

First walkthrough · 2 of 4

Review the epic before building it

/cpm-next:review docs/epics/01-01-epic-loans-csv-export.md
  • Three roster personas, each in its own subagent on Opus, read the epic independently. They get none of the conversation that produced the plan.
  • They look for criteria do could not verify, missing edge cases, work that looks simple and is not, wrong **Blocked by** lines, Must Have requirements no story covers, and conflicts with ADRs, the library or the code.
  • Critical and Warning findings with a clear fix are fixed in Pending stories, with an **Amended** line. Findings that would change scope go to Needs you, unfixed.
  • A review record is written to docs/reviews/.

First walkthrough · 3 of 4

Build one story

/cpm-next:do 1

With a story number and no epic, do uses the lowest-numbered In Progress epic, else the lowest-numbered epic with nothing started.

  1. Before the first story it reads CLAUDE.md, the library, the epic and its spec, finds the test command, and runs the suite to record a baseline.
  2. Sets the story In Progress and, with cpm-next-models, sets the story's effort.
  3. Builds it task by task, following the project's existing conventions.
  4. Verifies every acceptance criterion and writes an Evidence line under each.
  5. Hands the story to the auditor. On fix needed it fixes Critical and Warning findings and audits once more.
  6. Closes the story in the same edit as its **Audit** line.

The run ends with Blocked on me, Changed and Found. Commits, branches and pushes are left to you.

First walkthrough · 4 of 4

Check where things stand

/cpm-next:status

A read-only, one-screen report from docs/ and git. Nothing is written.

Where it stands

What the project is, what has been built, recent work, and what is in flight.

Needs you

**Pivot deferred** lines, stories blocked by a Not met criterion, open discussions, and suspect records such as a Complete story with a criterion that has no evidence.

Next

The commands worth running, most useful first.

Then finish the epic: /cpm-next:do docs/epics/01-01-epic-loans-csv-export.md. When the epic reaches Complete, do writes a short retro to docs/retros/, or adds **Retro waived**: clean run to the epic header.

Unattended runs

/cpm-next:do all

Runs every unfinished epic in dependency order. It is done when no unblocked story remains, and the full suite passes or any failures were failing before the run.

What it does not stop for

  • A test failure it cannot explain.
  • A criterion that contradicts reality, where fixing it would change scope.

For these it marks the story blocked with the reason and moves on to other unblocked work.

What always stops it

A destructive action, or one that reaches outside the repository: deleting data, rewriting history, touching shared infrastructure.

What "blocked" means

The story has a Not met line under a criterion, saying what was tried:

- Exports of 50,000 rows stay under 64 MB peak memory `[feature]`
  - Not met: streamed with a cursor; peak was 180 MB in the
    seeded test; cause not found

Stories that depend on it stay blocked, because it is not Complete. /cpm-next:status lists it under Needs you.

A scope change in an unattended run is made in that epic only, with an **Amended** line and its citation. Each upstream document that now disagrees gets a **Pivot deferred** line, which plan resolves later with you. A criterion is never changed because it is hard to meet.

Story effort and model

**Effort** and **Model**

What plan sets

  • **Effort**: high where a mistake is costly or hard to see: security, authorisation, migrations and other data changes, concurrency, executable scripts and hooks.
  • **Effort**: low for mechanical edits: a config value, a copy change, a rename, a row in a table.
  • No field means medium.
  • **Model**: haiku only on a low story whose edit is fully determined by the story.

Neither field changes what the story must deliver or how it is audited.

What do does with them

  • With cpm-next-models, it builds each story at that effort, and raises it to high (or xhigh for a high story) for the fix after a failed audit.
  • In a do all run no story goes below high.
  • A Haiku story is built by a Haiku subagent.
  • Without the mod, do builds at the session's effort.

The footer shows what is held, for example cpm-next:do · story 3 · sonnet · low. /cpm-models shows it; /cpm-models off releases it.

Agents

The auditor and the scout

auditor · Opus · read-only

Started by do before each story, or small change, is closed. It gets none of the builder's conversation and checks what is on disk.

  • Each criterion against its evidence, re-running the tests the evidence names.
  • The diff for defects, security problems, data loss and queries whose memory grows with the data.
  • Scope creep, and anything the story asked for that is missing.
  • Departures from CLAUDE.md, the library and existing patterns.
  • Tests that assert nothing, or were weakened or skipped.

Returns Verdict: pass or fix needed. Any Critical or Warning finding means fix needed. It never edits files.

scout · Haiku · read-only

Started by plan and do for lookups: where something is defined or used, which files match, what a config value is, what a read-only database query returns.

  • Answers with path:line references or the query and its result.
  • Runs only SELECT, SHOW, DESCRIBE or EXPLAIN, and does not read .env files.
  • Makes no judgement calls and recommends no changes.

Search output stays out of the main conversation, which every later request would otherwise carry.

Keeping up to date

Updates install at start-up and reach open sessions

  • The marketplace auto-updates when Claude Code starts.
  • plugin-sync checks every five minutes, and after each answer, whether the installed versions differ from the ones the session loaded. When one does, it shows a one-line notice and runs /reload-plugins, which waits until the session is idle.
  • plugin-sync does not install updates. A session that was open before you installed it needs one manual /reload-plugins; after that it reloads itself.

To update straight away, from any directory:

claude plugin marketplace update ninthspace-marketplace
claude plugin update cpm-next@ninthspace-marketplace   # and each other plugin that changed
